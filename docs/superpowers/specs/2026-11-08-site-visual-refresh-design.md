# 網站視覺翻新（書卷風格）— 設計文件

**日期：** 2026-11-08
**範圍：** 前台（`src/app/(frontend)`）整體視覺、Tailwind 設定、UI 元件程式碼整理。後台 admin 與資料結構不在範圍內。

標記說明：**【業主決定】** 是業主在討論中明確選擇的；**【設計者決定】** 是寫文件的人代為決定、業主未逐項確認的，實作者可以在不違背業主決定的前提下微調。

討論時用過的草稿保存在 `.superpowers/brainstorm/75780-1794072499/content/`（`article-directions-v2.html`、`toc-mobile.html`、`home-b.html`、`hero-options.html`），可以直接用瀏覽器打開對照。注意：草稿裡 `<p>` 的字級被草稿框架的 CSS 蓋掉，顯示得比設計小，數值以本文件為準。

## 1. 為什麼要做

業主覺得網站「整體都不好看」，尤其是文章頁。現況的具體問題：

- 五月做過一份設計規範（`DESIGN.md`），但只套用了一部分，文件與實際設定有多處數字矛盾（圓角 14 vs 16、主色 hex 前後不一），新舊風格混在一起。
- `layout.tsx` 的 `<body className="bg-primary/10">` 蓋掉了設定好的背景色，整站變成淡紫色；文章分隔線中間的點因為用 `bg-background` 而多出一個白色方塊。
- 字體只設定了英文 Geist，中文交給系統預設，在 Windows 上粗糙不一致。
- 文章頁：標題壓在整片黑色漸層上（沒有封面圖時只剩黑色漸層）、H2 用淡紫色、表格全部置中且行高過大、日期是美式 `09/26/2026`、作者用英文 `and` 連接、一行大約 48 個中文字（太長）。
- 程式碼：圓角 class 有 10 種寫法混用；`dark:` 碎片殘留但網站其實沒有深色模式；`RichText` 的 Tabs 轉換器會在頁面上多印一個「,」；Tailwind 設定檔 370 行，業主不會調。
- 部分手機瀏覽器（例如 Samsung Internet）會自動把網站轉成深色，因為網站沒有宣告只支援淺色，結果顏色錯亂。

業主是 Payload 和程式設計的新手，希望之後能自己改顏色、字體等設定。

## 2. 目標、非目標、反目標

**目標**

1. 文章頁變成「認真的刊物」式閱讀體驗，並附自動目錄。
2. 整站統一成同一套視覺語言（書卷風格），同類元件只有一種圓角、一種邊框、一種按鈕樣式。
3. Tailwind 升級到 v4，所有設計設定集中在一個 CSS 檔裡，加中文註解，讓新手能找到「主色改這一行」。
4. 修好現有的 bug 與怪設定（見第 7 節）。
5. 整理 UI 元件程式碼：只用設計 token，不用散落的原始色值；拿掉沒用的程式碼。

**非目標**

- 不改 Payload 的 collection、block、editor 設定，也不改資料結構。現有內容不需要重新編輯。（唯一的例外見第 7.4 節，只加 HTML `id`，不動資料。）
- 不做深色模式。【業主決定】
- 不改後台 admin 的外觀。
- 不改文案內容（只改日期、作者連接詞這類由程式產生的文字）。

**反目標（做到了也算失敗的情況）**

- 回到淡紫色當大面積背景、毛玻璃、大圓角加陰影疊來疊去的「糖果感」。
- 社交條、公告列、選單、footer 被改得不像原版（業主明確說原版比較好看）。
- 舊文章或頁面因為樣式改動而版面錯亂（例如表格在手機上爆版、編輯設定的置中對齊失效）。
- 表單、書單訂購、CEF 計算器、預約時段等互動功能因為元件重寫而壞掉。

## 3. 限制

- **不動 editor**：文章只能由以下元件組成，設計只能替這些元件換樣式：段落（粗體、斜體、底線、連結、對齊）、H1–H4、分隔線、表格，以及區塊 Banner、Code、MediaBlock、YouTube、CallToAction、Quote、CEFCalculator、Tabs。文章 editor **沒有**項目符號清單，所以「重點摘要」實際上是一個 H2 加幾段粗體開頭的段落。頁面（Pages）的 layout 區塊另有 Content、Archive、Collapsible、TimeSlot、Form、Timeline、BookList。
- **只做淺色**，並且要宣告 `color-scheme: light`，讓瀏覽器不要自動轉深色。【業主決定】
- **Tailwind 升級到 v4**，刪除 `tailwind.config.mjs`。【業主決定】
- 自架部署（PM2，`ecosystem.config.cjs`），不是 Vercel。`pnpm build` 時要能連網，才能抓 Google Fonts（`next/font/google` 會在 build 時下載字型並自架）。
- 專案沒有測試套件（見 `CLAUDE.md`），驗證靠 `pnpm lint`、`pnpm build` 和截圖比對，不要新增測試框架。
- 本機資料庫沒有資料，`data-backup/` 只有兩筆課程 JSON。業主**不會**提供正式站的資料庫備份。【業主決定】不過本機的 `public/media/` 已經有 1179 個圖片檔（包括文章封面和首頁大圖）。所以驗收用的資料由實作者從正式站的**公開 REST API**（`https://www.hk-hphi.com/api/...`）讀取已發佈的內容，匯入本機的 docker Mongo：pages、posts、courses、tutors、categories、media 的資料，以及 Header、Footer globals。只能用 GET 讀取，不能對正式站做任何寫入。匯入腳本放在 repo 以外的暫存位置，不要提交。如果匯入太困難，就退回第 8 節的備案。【設計者決定】
- 工作在 `feat/visual-refresh` 分支上進行（已建立）。pnpm 12.18 的升級已經單獨提交為 `chore: bump pnpm to 12.18.0`，之後重新產生 lockfile 一律用 pnpm 12.18。
- **執行方式**：業主要求可以交給 sub agent 的工作就用 sub agent，而且盡量用夠用的最小模型。機械式工作（改 class 名、改 token、搬檔案、簡單的工具函式）用 Haiku 5.5；一般元件改寫用 Sonnet 5.5；只有需要判斷整體設計或處理疑難的步驟才用 Opus。【業主決定】

## 4. 視覺方向

### 4.1 整體：書卷風格（業主在三個方向中選了 B）【業主決定】

米白紙色背景、明體（宋體）標題和內文、細線條、小圓角、不用陰影。紫色只用在小地方：小標籤、目錄高亮、引言、分隔線裝飾。深紫色（anchor）用在主要按鈕和 CTA 色帶。

字體分工【設計者決定】：

- **明體**（Noto Serif TC）：所有標題、文章內文、頁面裡的長文（`prose`）、卡片標題、引言。
- **黑體**（Noto Sans TC）：選單、按鈕、小標籤、表單、日期與作者等資訊、卡片摘要、表格、目錄。
- 等寬字：系統 `ui-monospace`，只用在 Code 區塊。
- 移除 Geist（`geist` 套件若不再使用就一併移除）。
- 字型用 `next/font/google` 載入，`preload: false`、`display: 'swap'`，字重只載入需要的：明體 500／600／700，黑體 400／500／700。fallback 依序放 `PingFang TC`、`Microsoft JhengHei`（黑體）與 `Songti TC`、`PMingLiU`（明體）。

### 4.2 設計 token【設計者決定，數值取自草稿】

| 名稱（用途） | 值 | 用在哪裡 |
|---|---|---|
| paper（頁面底色） | `#f7f4ee` | `body` 背景 |
| paper-raised（浮起的面） | `#fbf9f5` | 卡片、輸入框背景 |
| paper-sunken（下沉的面） | `#efe9df` | 次要區塊底色、hover |
| ink（主要文字） | `#2b2622` | 內文、標題 |
| ink-soft（次要文字） | `#4a423b` | 副標題、hero 說明文字 |
| muted（輔助文字） | `#7a716a` | 日期、作者、圖說、placeholder |
| line（線） | `#e2dbd0` | 邊框、分隔線、表格線 |
| line-strong（較深的線） | `#d9d1c6` | Banner 上下線、卡片 hover 邊框 |
| iris（品牌紫） | `#6241a0` | 小標籤、目錄高亮、連結底線、focus、公告列 |
| iris-soft（淡一階的紫） | `#8865bb` | H2 編號 |
| lilac（裝飾紫） | `#b9aacd` | 分隔線菱形、細裝飾 |
| anchor（深紫） | `#3d2b5f` | 主要按鈕、CTA 色帶、footer、文章導言文字 |
| success／warning／error | 沿用現值（sage `#5a8a64`、amber `#c08a2b`、madder `#b8413f`） | 狀態、Banner |

- **圓角**：`0`、`2px`、`4px`（預設：按鈕、輸入框、卡片、圖片）、`8px`（彈出視窗、下拉選單）、`full`（膠囊標籤、頭像、圓形圖示按鈕）。不准出現其他值。【業主同意縮小圓角；數值由設計者決定】
- **陰影**：平時一律不用。只有浮在上面的東西（下拉選單、彈出視窗、手機目錄展開的面板）可以用一種柔和陰影。
- **focus**：`iris` 1px 邊框加 3px `iris`/25% 外圈。
- token 一律在 CSS 裡定義，元件只能用 token，不能寫 `bg-gray-300`、`bg-green-500` 這類原始色。唯一例外是 WhatsApp 的品牌綠。

### 4.3 保留原版的部分【業主決定】

**社交條（Social Strip）、公告列（Announcement）、選單（Header／nav，含手機選單）、footer** 保留目前的版面、顏色和樣子。允許的改動只有：

- 圓角改用新的圓角尺寸；
- 字體跟著全站換成 Noto Sans TC；
- 背後的程式碼整理（用 token、拿掉沒用的 class）；
- **只在手機上（< 768px）** 把社交條和公告列縮小一點，例如 QR 縮小、上下內距和字級減少，讓文章開頭早一點出現。版面和顏色仍然是原版。這兩條本來就可以關掉，所以只要適度縮小，不用壓到最小。【業主決定】

要注意：這些元件現在的顏色是透過 `--background`、`--muted`、`--primary` 等 token 間接得到的，社交條的淡紫底還疊在 `body` 的 `bg-primary/10` 上面。token 改成書卷色系之後，它們會跟著變色。實作時要先截圖記下正式站目前的樣子，再替它們指定固定的顏色（例如另外定義 `chrome-*` token），讓外觀維持不變。公告列目前是 `bg-primary`（≈ iris）、footer 是 `bg-anchor`，剛好與新 token 同色。

如果放到米白頁面上後，選單底色看起來明顯不協調，可以在驗收時提出微調建議，但不要自行改動。

## 5. 文章頁（`/posts/[slug]`）

整體以書卷風格為主，加上「知識指南」方向的自動目錄。【業主決定】

### 5.1 文章頂部（取代 `PostHero`）

- 置中排列：分類小標籤（黑體、iris、字距加寬，多個分類用「 · 」連接）→ 標題（明體 700，桌面約 40px、手機約 24px，行高 1.45）→ 作者與日期（黑體、muted）→ 一條 40px 長的 lilac 細線。
- 日期格式改成 `2026年9月26日`。作者多於一位時用「、」連接，不再用英文 `and`。【設計者決定】
- 顯示「閱讀約 N 分鐘」：由內文文字長度推算，每分鐘 400 個中文字，至少 1 分鐘。【設計者決定】
- 封面圖（`meta.image`）放在標題下方，寬度等於網站內容容器（不是整個視窗寬，最寬約 1120px），比例約 2:1、高度最多 560px；手機為滿版寬、比例約 4:3。沒有封面圖就不顯示這一塊，標題區照樣成立，不再出現黑色漸層。【設計者決定】

### 5.2 內文

- 內文欄寬約 620px（大約 34 個中文字），明體 500，桌面 18px、行高 2.0；手機 16–17px。
- **導言**：內文的第一個段落自動放大（約 20px、600、anchor 色）。如果第一個節點不是段落（例如圖片），就沒有導言樣式。
- **H2**：明體 700，約 27px，置中。標題上方有一個小編號（`01`、`02`…，黑體、iris-soft），和目錄的編號一致。
- **H3**：明體 700，約 21px，靠左。**H4**：黑體小字、iris、字距加寬，當作小標籤用。
- **分隔線**：不畫線，改成置中的三顆 lilac 小菱形（`◆　◆　◆`）。不能用會跟底色不一致的背景色塊。
- **連結**：ink 色文字加 iris 底線，hover 時文字變 iris。【設計者決定】
- **表格**：黑體 15px、靠左對齊、表頭下方 2px ink 線、每列 1px line。手機上包一層可以橫向捲動的容器，不能撐破版面。
- **引言 Quote**：置中、明體 600、約 25px、anchor 色，前後加「」；作者用黑體小字、muted、字距加寬。
- **提示框 Banner**：不用色塊，改成上下兩條 line-strong 細線，上方有一個黑體小標籤，顏色依樣式：info 用 iris、success 用 sage、warning 用 amber、error 用 madder。標籤文字由實作者決定，建議分別用「提示」「重點」「注意」「重要」。
- **MediaBlock**：圖片寬度等於內文欄寬，不向兩側延伸，以免在桌面上蓋到左側的目錄；4px 圓角；圖說黑體 13px、muted、置中。【設計者決定】
- **YouTube**：與 MediaBlock 同寬，4px 圓角。
- **Code**：深色底（ink）、4px 圓角，保留複製按鈕。
- **CTA（在文章裡）**：與頁面上的 CTA 同樣式（見 6.4），但限制在內文欄內，4px 圓角，不滿版。
- **CEFCalculator、Tabs**：套用第 6.5 節的共用表單與分頁樣式。
- **相關文章**：區塊標題「相關文章」（明體、置中、下方 iris 短線），下面是三欄卡片（見 6.3）。

### 5.3 目錄（Table of Contents）【業主決定版面；細節為設計者決定】

- 由文章內容裡的 **H2** 自動產生，編輯不用做任何事。文章的 H2 少於 2 個時不顯示目錄。
- 每個 H2 在輸出的 HTML 加上 `id`（例如依序 `section-1`、`section-2`），讓目錄可以連過去。這只改渲染結果，不改資料。
- **桌面（寬度 ≥ 1280px）**：目錄放在內文欄左側的空白處，跟著捲動（sticky），寬約 190px。每一項是「編號＋標題」，目前讀到的那一節用 ink 粗體加 iris 編號標示。
- **手機和平板（< 1280px）**：
  1. 第一段（導言）後面放一個目錄框：上下細線，左邊「目錄」，右邊「N 節　展開 ▾」，預設收起，點一下展開完整清單。
  2. 往下捲過這個目錄框之後，sticky header 下方出現一條薄的置頂小條（約 36px）：「目錄｜04　目前章節標題 ▾」，底部有一條 2px 的 iris 閱讀進度條。點小條就從上方展開完整目錄，後面的內容變暗；點選某一節後平滑捲動過去並收起。捲到相關文章區時小條消失。
- 跳轉時要扣掉 sticky header（以及小條）的高度，標題不能被蓋住。
- 支援 `prefers-reduced-motion`（減少動態時不用平滑捲動）。可以用鍵盤操作，展開狀態要有正確的 `aria-expanded`。

### 5.4 `/single-post/[slug]`

這條路由目前與 `/posts/[slug]` 幾乎重複，程式碼裡沒有任何地方連到它，但可能有外部舊連結。保留網址，改成與 `/posts/[slug]` 共用同一個文章版面元件。【設計者決定】

## 6. 其他頁面與元件

### 6.1 首頁大圖（HighImpact hero）【業主選了第 3 個方案】

- 圖片照樣滿版。圖片上疊一層由左到右的漸層：從 paper 97% → 34% 處 90% → 66% 處透明。文字直接放在左邊淡掉的地方，不用方框。
- 標題明體 700，約 46px（手機約 30px），文字為 ink 色（目前的 `prose-invert` 沒有生效，一併拿掉）。說明文字 ink-soft。按鈕用主要按鈕樣式。
- 拿掉右上角的 IrisMark 裝飾。
- 手機【設計者決定】：左右漸層在窄螢幕上效果不好，改成圖片在上（約 4:3）、往下漸漸淡成 paper，文字放在下面。
- hero 的文字來自編輯填的 rich text，要尊重編輯設定的對齊方式。

### 6.2 MediumImpact、LowImpact hero【設計者決定】

- **MediumImpact**：左文右圖，各佔一半（草稿 `hero-options.html` 的第 1 個方案）。圖片 4px 圓角，不加邊框和陰影，拿掉 Bloom 裝飾。手機上文字在上、圖片在下。
- **LowImpact**：只有文字，置中的明體大標題（草稿第 2 個方案的文字部分），沒有圖片。

### 6.3 卡片（課程、文章、搜尋結果、相關文章）【業主說新的比較好看】

- paper-raised 底、1px line 邊框、4px 圓角、沒有陰影。
- 上方圖片比例 4:3。內容區：有分類資料時才顯示分類小標籤（黑體 12px、iris、字距加寬），然後是明體 700 約 19px 的標題、黑體 14px 的摘要（最多 3 行），最後是一行加底線的文字連結：課程用「了解課程」，文章用「閱讀全文」。
- 整張卡片都可以點。hover 時邊框變 line-strong、標題加底線，不浮起來。

`/tutors` 目前不是卡片，而是「人像＋文字」左右交替的整排版面，加上 `01/02` 編號。這個版面保留不變，只換成新的字體、顏色和圓角。導師詳細頁、課程頁、文章列表、搜尋頁和 404 頁也一樣：版面不變，只套用新的 token 和字體規則。【設計者決定】

### 6.4 CTA（CallToAction 區塊）【業主說新的比較好看】

- 拿掉毛玻璃、Bloom 和 IrisMark。在頁面上是一條滿版的 anchor 深紫色色帶：左邊明體標題（paper 色，約 30px）和黑體副標題（淡紫灰），右邊按鈕。按鈕用 paper 底、anchor 字；第二個按鈕用白色外框。
- 在文章裡就限制在內文欄內（見 5.2）。

## 7. 技術整理

### 7.1 Tailwind v4

- 先用官方升級工具（`npx @tailwindcss/upgrade`），再手動修正。PostCSS 改用 `@tailwindcss/postcss`，移除 `autoprefixer` 和 `tailwindcss-animate`（改用 `tw-animate-css`）。typography 用 `@plugin "@tailwindcss/typography"`。
- 所有設計設定（顏色、字體、字級、圓角、陰影、動畫）寫在 `src/app/(frontend)/globals.css` 的 `@theme` 裡，依類別分段，每一段和每個 token 都加上**中文註解**，說明用途和用在哪裡。文章和 `prose` 的樣式很長，可以拆到同目錄下另一個 CSS 檔再 `@import` 進來。
- 刪除 `tailwind.config.mjs`。原本的 `safelist` 改成 `@source inline(...)`，先確認每一項是否真的還需要。
- 更新 `components.json`（v4 的 `tailwind.config` 留空）。`src/cssVariables.js` 的斷點要與 CSS 保持一致。
- 注意 v4 的預設值改變：預設邊框色、`ring` 寬度、`shadow-sm` → `shadow-xs` 等重新命名。改完後要逐頁檢查。

### 7.2 深色模式與底色

- 移除 `darkMode` 設定和所有 `dark:` class。
- 在 `<head>` 加上 `<meta name="color-scheme" content="only light">`，CSS 加上 `:root { color-scheme: only light; }`。要寫 `only`，瀏覽器的自動深色功能才不會套用。
- 移除 `<body className="bg-primary/10">`，背景改用 paper token。

### 7.3 字體

見 4.1。字型變數接到 `@theme` 的字體 token，標題和內文的對應寫在 CSS 裡，不要散落在各元件。

### 7.4 RichText 與文章

## 10. 風險

- **中文網頁字型很大**：Google Fonts 會把中文字型切成很多小片段（unicode-range），瀏覽器只下載用到的片段，但第一次載入仍然比現在重。要確認 `display: swap` 有生效，而且沒有預先載入整套字型。
- **Tailwind v4 需要較新的瀏覽器**（Safari 16.4 以上、Chrome 111 以上）。2026 年的香港使用者基本都符合，但很舊的 iPhone 會看到沒有樣式的頁面。
- **保留原版的元件可能變色**（見 4.3），要先截圖再動手。
- **編輯過去的排版習慣**：舊內容可能用了置中對齊、空段落、在表格裡放長段文字等做法，改樣式後要用真實資料檢查。
